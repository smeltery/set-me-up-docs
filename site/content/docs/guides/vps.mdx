## Prepare the host

Start on a headless Debian or Ubuntu host that you can reach over SSH. Use an account with sudo for installing system packages, and run the bootstrap as the user whose home directory will hold the blueprint.

Install the tools below, then follow Quick start to configure your fork and download and inspect smu-bootstrap.sh. Keep SSH credentials and host-specific secrets outside the blueprint.

```bash title="Terminal"
sudo apt-get update
sudo apt-get install -y bash curl git ca-certificates python3
```

<span id="preview" />

## Preview the platform bootstrap

Select platform submodules to limit what the bootstrap checks out. Review the repository, branch, destination, and submodule scope.

Platform scope keeps shared repositories and the Debian module checkout where your blueprint declares them. It skips the Mac-specific module checkouts. The plan’s submodule_scope value should be platform.

```bash title="Terminal"
SMU_SUBMODULE_SCOPE=platform bash smu-bootstrap.sh --no-header --plan --json
```

<span id="install" />

## Install the blueprint

Use the same platform scope when you run the reviewed bootstrap.

Open the checkout in the current SSH session and verify the bundled CLI as shown in Quick start. If the smu command is unavailable, use the temporary Bash function from that guide.

```bash title="Terminal"
SMU_SUBMODULE_SCOPE=platform bash smu-bootstrap.sh --no-header
```

<span id="plan" />

## Plan server provisioning

Inspect the VPS profile, modules, and expected changes before provisioning.

Look for the server/headless module, then review its package list and any conflict, secret, or trust findings. If that module cannot be resolved, check whether dotfiles/modules/debian is initialized before retrying.

```bash title="Terminal"
smu plan --machine vps --json
```

<span id="provision" />

## Apply the server profile

Use the vps profile for the targeted server setup. It provisions the Debian server/headless module instead of the workstation package set.

This command can install Debian packages and prompt for sudo. Run it after checking the plan and reviewing the server/headless package list.

```bash title="Terminal"
smu --setup-profile vps
```

<span id="verify" />

## Verify the server setup

Check the Debian module in the status output and review any partial or missing package entries. If the setup profile rejects the host, check that the machine is a Debian or Ubuntu system rather than retrying with a workstation profile.

```bash title="Terminal"
smu status --search server/headless --json
```

## Choose a Nix path if needed

Use Home Manager for user-level provisioning when Nix and Home Manager are installed on the host. Use the NixOS adapter only on a NixOS host.

The server setup command above follows the rcm provisioning path for the Debian baseline module. For a Nix-managed setup, select the Nix adapter in smu.toml and use its separate preflight and apply workflow.
