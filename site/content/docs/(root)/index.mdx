## How it fits together

The blueprint is your Git repository. It contains dotfiles, module selections, and the settings that tell smu how to provision them. The bootstrap downloads that repository and its selected submodules, including a bundled copy of the installer.

A module is a unit of work, such as a package list or a setup script. A profile selects a group of modules, while an adapter determines how to apply them. For example, a desktop profile can use Home Manager for modules that publish Nix definitions and rcm for a shell module during a hybrid migration.

## A typical setup session

Review the target repository and the scripts it runs. Install the blueprint into the directory you intend to keep, then use the bundled CLI to inspect the profile and module state.

Apply one reviewed module first. Check that it did what you expected before adding the rest. When you move to another machine, start with the same blueprint and choose the profile that fits that host.

## Maintain a setup

Check what a module changes before applying it. Preview updates to an installed checkout before switching to new configuration.

Use the status report to distinguish missing packages from script modules that have no detection marker. If an update is blocked by local work or a provisioning step fails, review the relevant diagnostic before retrying.
